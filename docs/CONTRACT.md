# 灵语 Chat 1.0 — implementation contract

Independent Windows Electron app; old fishpond app untouched. Chinese UI, Telegram-inspired chat-first 3-column layout using MIT Chatscope React components. No official Telegram/AI vendor affiliation. No prefilled fake AI chat. Personas are fiction, model binding separately displayed. User-provided reference art stays local with source/attribution intact. No file deletions.

## Ownership
Root: main.cjs/preload.cjs, media/speech, build/package, assets, integration/QA/docs.
core agent: src/core/store.cjs, src/core/harness.cjs, src/data/agents.json, tests/core.test.cjs, tests/harness.test.cjs.

## Data and core
ChatStore({dir,encrypt,decrypt}) encrypt(string)->base64 ciphertext; decrypt(ciphertext)->string. Throws rather than plaintext fallback. Append-only JSON snapshot files, latest valid load. getPublic() returns cloned {schema:1,providers:[],agents:[],conversations:[],messages:{[conversationId]:[]},drafts:{},settings:{displayName:'我',autoVoice:false,theme:'light'},greetings:{}}. Secret-bearing state never reaches renderer. providers public {id,name,baseUrl,model,vision:boolean,consent:boolean,hasKey:boolean}; secret {apiKey}. saveProvider(input) optional apiKey (blank keeps key), endpoint accepts HTTPS or loopback HTTP only, URL credentials/query/fragment disallowed. Changes to endpoint must clear prior key unless newly supplied, never re-route old key silently. getProvider(id) returns secret-bearing internal only. agents {id,name,subtitle,avatar,accent,persona,memory,providerId,greeting:{enabled:false,hour:10},voice:'',tags:[]}. Persona/memory user editable; import/export agent JSON allowlisted, never credentials/history. Imported agent unbound to provider. exportAgent(id), importAgent(card), saveAgent(input), updateSettings(input), createConversation({agentId,type:'ai'|'peer',name?,peerId?}) => conversation; setConversation({id,pinned?,archived?,read?}); saveDraft({conversationId,text}); addMessage(conversationId,{id?,role:'user'|'assistant'|'peer'|'system',text,attachments:[],status:'sent'|'pending'|'failed'|'cancelled',source:'ai'|'user'|'peer'|'local',model?,createdAt?,replyTo?,greeting?}) => message; patchMessage(conversationId,id,patch); getMessages(id); getConversation(id); markGreeting(agentId,day). All validation and length caps in core, not renderer alone.
Message attachment {id,type:'image'|'audio',mime,name,url:'lingyu-media://asset/<id>',bytes}; no renderer filesystem paths. Root media resolver validates ids and MIME, persists original media to unique files; models receive data URLs only if configured vision=true.

Harness({store,fetch,resolveImage,onEvent,log}) .send({conversationId,text,attachments:[],clientId?,replyTo?,retryMessageId?,greeting?:true}) returns {message}; .cancel(conversationId). fetch injection Electron net.fetch production. One active request/conversation; bounded context 24 messages plus persona and explicit memory; 90sec timeout, cancellable, user message preserved on failure. A retry references existing user message, does not duplicate. Empty response/error/truncated response never treated as success. Standard OpenAI-compatible /chat/completions payload, SSE streaming if supported; minimal max_tokens 4096, no extra vendor-only parameters. No tool execution from messages. Event {type:'state'|'delta'|'status',conversationId,messageId?,text?,status?}; renderer can bootstrap after state event. Logs metadata only (model/request/status/token/time), no keys/text/images. .replyExternal({agentId,text,attachments?,signal?}) uses persona only, excludes owner's private memory/history, rate limits managed by root, no persisted local chat. User image with vision=false rejected before dispatch, with actionable message. Runtime is modular session/persona/model/media/scheduler/channel architecture inspired by DSH, not actual DSH shell tool runtime.

## P2P module contract
ES module src/p2p/peer.js exports PeerLink class. constructor({onState,onMessage,onError,iceServers=[]}); async createOffer({name,mode:'human'|'agent',agentName?})=>invitation string; async acceptOffer(invitation,{name})=>answer string; async acceptAnswer(answer); send({type:'chat'|'agent-request'|'agent-response'|'error',id,text,attachments?:[{dataUrl,name,type}],requestId?,model?}) => Promise; close(). Getter info {sessionId,remoteName,mode,connected,route?}. Native RTCPeerConnection/DataChannel. Non-trickle compact manually exchanged invitation/answer, complete ICE timeout, strict bounded schema/code/frame sizes. Chunk media, max total8MB/message, no remote URL downloads, max16KB chunks/backpressure, duplicate ids ignored, 30sec transfer timeout. State callbacks {status:'new'|'connecting'|'connected'|'disconnected'|'closed',info}. RTC connection DTLS encrypted, manual invite includes network metadata; both apps must remain open. Default no third party signaling; optional user STUN/TURN config, no promise internet reachability. Peer messages not auto-forwarded to AI except explicitly accepted agent-sharing session. AI replies tagged AI with actual model; human mode messages tagged peer. No HTTP/QQ account polling.
