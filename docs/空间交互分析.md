# 空间交互分析：公开行为、数据流与本机实现

核验日期：2026-11-05。本任务中的 reverse 指研究交互思路与数据流，随后独立实现适合本应用的功能，不复制 QQ 源码、账号数据或素材。

## 方法与证据边界

[REA 官方 README](https://github.com/morluto/rea/blob/main/README.md)描述的工作方式是：围绕具体功能追踪程序、代码与运行行为，给出证据及局限，再实现并测试自己的版本；网页分析可涉及页面结构、脚本和网络观测。本次借用这一分析顺序，**没有安装、启动或调用 REA，也没有使用 REA 反编译 QQ**。实际工作是只读获取公开页面及其显式脚本，再审查本应用自己的源码与测试。

使用不带 Cookie、账号或现有浏览器登录态的独立 HTTP 请求，取得 [QQ 空间公开入口](https://qzone.qq.com/)的 HTML：39,839 字节，SHA-256 为 `92e83a287c8d85871a1ce6bd46c2324622695288cdfc3515a3f4bd478b94a418`。HTML 含 `ui.ptlogin2.qq.com/cgi-bin/login` 登录 iframe，以及登录相关脚本标记。它显式引用的 [公开配置脚本](https://qzonestyle.gtimg.cn/qzone/qzactStatics/configSystem/data/179/config1.js)为 1,269 字节，SHA-256 为 `29f4faf2d12cc7e789d807ff38b1d12167d9559519032f02b49bb3e6896404dd`；仅静态读取，没有执行。

这些内容是未登录入口与配置，**没有观察到已登录动态流、真实评论请求、发布回执或 QQ 后端结构**。公开登录页不能证明登录后的业务规则，更不能据此给 QQ 内部字段、数据库表或失败策略下结论。

腾讯的[QQ 空间产品介绍](https://www.tencent.com/zh-cn/products/qzone/)可确认日志、说说、相册、视频和留言等产品层功能。另有公开的[《QQ 隐私保护指引》2024-10-16 版](https://private-70457.njc.vod.tencent-cloud.com/3f1b9192-8b71-11ef-a0fe-eeb9d133b947)，第 6.5.2—6.5.4 节区分动态、互动评论和空间访问的范围设置。它是历史版本的一手文档，只用于说明权限概念分层，不宣称其中菜单路径在当前客户端保持不变。

## 观测、推断与本应用对应

| 观测：当前有证据支持什么 | 推断或设计选择：不冒充 QQ 内部事实 | 本应用实现：已存在与仍缺什么 |
| --- | --- | --- |
| 公开 QQ 入口需要登录；此次没有进入真实 feed。 | 登录身份、内容可见范围与写权限应分别检查。能看到不等于能评论、代替作者发布或访问私聊。 | `main.cjs` 的统一 IPC `bind` 检查调用窗口与 frame；空间发文、普通评论由主进程固定 `authorId:'me'`、`source:'user'`，角色评论需单独走模型生成入口。没有 QQ 身份、好友关系或多用户权限系统。 |
| 腾讯公开介绍将说说、相册、视频等列为不同功能；没有观测到其内部资源模型。 | 动态正文与媒体实体宜分层，卡片仅持有受验证的附件引用，避免把任意路径或 URL 当作可信媒体。 | 动态附件经 `media.validated`，由本机 UUID 与 `lingyu-media://asset/<id>` 引用。图片实际由媒体服务验证/重新编码。当前空间 UI 仅提供图片入口，没有 QQ 相册、视频上传或远端 CDN 功能。 |
| 未取得 QQ 评论接口，不能确认其真实参数是否叫 `postId`。 | 本应用的评论操作必须明确指向稳定的动态 ID，不能用当前列表下标、当前选中卡片或最新一条动态推测归属。 | `spaceComment({postId,text})` → `plugins.addComment` 按 ID 找目标；评论保存在对应 `post.comments` 中。`spaceGenerate({postId,...})` 也先验证目标存在。ID 是本应用自行生成的 UUID，不是 QQ ID。 |
| 历史官方隐私文档区分动态、评论与空间访问权限。未观测现网权限计算。 | “可见”“可互动”“可生成 AI”“可使用模型额度”应保持独立。不能因开启空间功能就默认读取私聊或使用外部账户。 | 本机空间开关控制写操作；AI 动态/评论由用户显式触发，并经角色模型的授权检查。生成路径调用 `replyExternal`，不带主人私有记忆或聊天历史。动态评论提示仅带目标正文和用户补充，当前不会自动带入整条评论线程。 |
| 未登录公开页无法观察 QQ 是否采用乐观更新、回滚还是确认后刷新。 | 若采用乐观更新，需要 `pending/failed` 状态、幂等请求 ID 与明确回滚；失败时应保留正文/媒体，避免把“点了发布”误当成功。 | 当前 UI 采用确认后刷新：先等待主进程持久化成功，再清空动态/评论输入与刷新。点赞也等待写入，没有先假增数字。没有宣称已复制 QQ 的乐观更新机制。 |
| 未获取 QQ 失败回执或弱网行为，不能断言它如何恢复草稿。 | 输入内容、已提交内容和界面刷新状态应分离；AI 失败不应伪造评论成功。 | `PluginStore.change` 先验证并写新快照，再切换内存状态；写入失败保留原状态。UI 写入失败时尚未执行清空输入。**空间编辑草稿目前只在 React 内存中，关窗/重启不保证恢复；评论也没有独立提交锁/幂等标识。** |
| QQ 公开资料说明面向亲友分享互动；本次没有观察真实用户数据。 | 本地仿社交体验必须区分用户本人、虚构角色生成内容与真实外部用户，不能制造已有点赞、访客或好友评论。 | `source:'user'|'ai'` 与 `authorId` 分开存储，UI 标注“AI 生成”；初始动态、评论为空。`liked` 只是本机用户的布尔状态，不是多人点赞计数。未实现跨设备空间同步或公开发布。 |

## 本机可追踪的数据流

```text
空间表单：正文 / 选中图片
  → preload 白名单方法 spacePost
  → main：固定本人身份 + 文字与本机附件验证
  → PluginStore.addPost：UUID / 时间 / 来源 / comments[]
  → change：克隆 → 验证 → 新快照写入 → 切换内存
  → state 事件与 bootstrap 刷新 → 动态卡片

目标卡片的评论框
  → spaceComment({postId,text})
  → main：固定本人身份
  → addComment：验证 postId 存在 → 只追加到该动态

用户选择角色并点“请角色评论”
  → spaceGenerate({postId,agentId,prompt})
  → main 验证目标与角色 → Harness.replyExternal（无主人私聊/私有记忆）
  → 真正收到模型结果后 addComment(source:'ai')
  → 持久化成功后刷新
```

源码位置：`src/ui/App.jsx` 的 `SpacePanel`、`src/preload.cjs`、`src/main.cjs` 的 `spacePost/spaceLike/spaceComment/spaceGenerate`，以及 `src/core/plugins.cjs` 的 `addPost/toggleLike/addComment/change`。这些是本应用自己的实现证据，不是 QQ 源码分析结果。

## 已验收与后续可验收项

本次执行 `node --test tests/plugins.test.cjs`，15/15 通过，其中已有空间发布/点赞/评论持久化、来源分离、媒体引用验证、开关禁止写入、快照恢复和非法 ID 测试。它们证明对应本机模块行为，不等于端到端 UI 或 QQ 兼容性测试。

后续交互验收可使用两条本机动态 A/B：向 A 评论后，只有 A 的评论数组和计数改变；给 B 点赞不会改变 A；无效 `postId` 不产生游离评论；模拟存储失败时原动态与输入仍保留；AI 请求失败不插入成功评论；停用空间后写操作失败但旧内容仍可读取。若要保证重启恢复空间草稿、避免评论重复提交，应先补持久化草稿和提交幂等机制，再作相应承诺。

本分析没有登录 QQ、读取 Cookie、抓取好友动态、复制私有代码、发布内容或操作任何 QQ 账号。
